HR-ACL-001 Critical Non-default principals with DCSync rights Access control 1

Description

These principals hold both 'Replicating Directory Changes' and 'Replicating Directory Changes All' on the domain. They can retrieve the password hash of any account, including krbtgt, without touching a domain controller's disk. Only domain controllers and the built-in administrative groups should hold these rights.

Remediation

Remove the replication rights from the domain object's DACL unless there is a documented need (e.g. Azure AD Connect / Entra Connect sync account). Treat any remaining holder as Tier 0: protect, monitor (event 4662 with the replication GUIDs) and rotate its credentials.

HR-ACL-002 Critical Dangerous permissions over Tier 0 objects held by non-Tier 0 principals Access control 2

Description

Non-privileged principals hold rights such as GenericAll, WriteDacl, WriteOwner, ForceChangePassword or AddMember over Tier 0 users, groups, computers, GPOs or containers. Each entry is a one-step escalation to Tier 0 for anyone who controls the principal.

Remediation

Remove the listed ACEs (fix inherited entries at the parent OU/container). Make sure privileged accounts and groups are protected by AdminSDHolder and that delegated administration (helpdesk, provisioning tools) is scoped to non-Tier 0 OUs only.

HR-ADCS-ESC1 Critical ADCS ESC1: enrollee-supplied subject on an authentication template ADCS 1

Description

Low-privileged principals can enroll in a published template that allows client authentication, lets the requester supply the subject (SAN) and needs no approval or authorized signature. They can request a certificate as any user, including a Domain Admin, and authenticate with it.

Remediation

Clear CT_FLAG_ENROLLEE_SUPPLIES_SUBJECT, or require CA manager approval. Restrict enrollment to the specific groups that need the template, and remove Domain Users / Authenticated Users / Domain Computers from enrollment rights.

HR-DELEG-001 Critical Unconstrained delegation on non-DC accounts Delegation 1

Description

Accounts trusted for unconstrained delegation receive a forwardable TGT from every user that authenticates to them. An attacker who controls one of these hosts can coerce a domain controller to authenticate (e.g. PrinterBug/PetitPotam) and capture its TGT, which leads straight to DCSync.

Remediation

Remove 'Trust this computer for delegation to any service'. Replace it with constrained delegation or RBCD scoped to the services required. Add privileged accounts to Protected Users or mark them 'Account is sensitive and cannot be delegated'.

Description

These accounts can impersonate any user to the listed services (S4U2Proxy). With protocol transition (TrustedToAuthForDelegation) no user interaction is needed at all. Delegation to services on Tier 0 hosts lets whoever controls the account take over those hosts.

HR-KERB-001 Critical Kerberoastable privileged accounts Kerberos 1

Description

Privileged user accounts have a service principal name (SPN). Any authenticated user can request a service ticket for them and crack the account password offline. A cracked Tier 0 service account is an immediate domain compromise.

Remediation

Remove SPNs from privileged accounts, or move the service to a group Managed Service Account (gMSA). Where an SPN must stay, set a random 30+ character password, enable AES-only encryption (msDS-SupportedEncryptionTypes) and remove the account from privileged groups.

Method

  • All analysis runs offline on SharpHound CE JSON; this file makes no network requests.
  • Tier 0: built-in privileged groups and accounts, domain controllers, domain objects and DCSync holders, expanded through nested group membership.
  • Attack paths: shortest paths over membership, ACL, local admin, session, delegation, GPO and containment edges. Sessions reflect collection time only.
  • Stale accounts are measured against the newest logon timestamp in the data (2025-12-30), threshold 90 days.
